# Korean prose quick rules

This project-authored checklist is the fallback for Korean prose meant for human readers: documentation, reports, Notion pages, and long email or Slack messages. Short chat replies, code, and logs are exempt.

1. Save the final draft before polishing. Mark facts, numbers, names, links, quotes, and table values as protected. Keep those passages byte-identical, including formatting within them; do not add claims or change the level of certainty.
2. Say who does what, using concrete verbs. For example, prefer `팀이 설정을 검토했다` to `팀에 의해 설정에 대한 검토가 이루어졌다`. Drop openings that merely announce the next sentence and conclusions that only repeat it. Keep transitions that show an actual cause, contrast, or sequence.
3. Compare the polish pass with the saved draft. Count character insertions, deletions, and replacements (including spaces and punctuation) relative to the original character count; use all of the Korean prose being polished, excluding exempt code and logs. Warn above 30%. Above 50%, stop: do not publish that revision, and return to the saved draft for a smaller pass.
4. Recheck protected passages against the saved draft before delivery. If any differ, restore them exactly and recheck the change rate. Report the checklist as a manual fallback, not as a plugin run.
